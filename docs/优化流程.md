# Node.js 博客系统企业级重构计划书

## 1. 项目现状分析 (As-Is)

*   **技术栈**: Node.js, Express (4.x), MongoDB (Mongoose 5.x), EJS 模板引擎。
*   **架构**: 经典的 MVC 分层架构。
*   **工程化程度**: 低。缺乏 TypeScript 类型约束，无自动化测试，手动部署 (bat 脚本)，无容器化，依赖本地环境。
*   **代码质量**: 缺乏统一的 Lint 规则，日志依赖 `console`，缺乏统一错误处理。
*   **安全性**: 基本的安全措施缺失 (如 Helmet, Rate Limit)。

## 2. 重构目标 (To-Be)

将该项目升级为符合现代企业级标准的 **TypeScript 全栈应用**，具备完整的 **CI/CD 流水线**、**自动化测试**、**容器化部署** 以及 **高性能/高可用** 特性。

## 3. 实施路线图 (Roadmap)

### Phase 1: 工程化基建 (Foundation)
**目标**: 统一开发环境，建立代码规范，容器化运行。

1.  **Docker 容器化**
    *   创建 `Dockerfile`: 定义 Node.js 运行环境 (多阶段构建优化镜像大小)。
    *   创建 `docker-compose.yml`: 编排 App, MongoDB, Redis 服务，实现一键启动开发环境。
    *   **关键文件**: `Dockerfile`, `docker-compose.yml`, `.dockerignore`

2.  **代码规范与 Linting**
    *   引入 `ESLint` + `Prettier`: 统一代码风格 (推荐 Airbnb 或 Standard 规范)。
    *   配置 `Husky` + `lint-staged`: 提交前自动检查代码风格，阻止烂代码入库。
    *   **关键文件**: `.eslintrc.js`, `.prettierrc`, `.husky/`

3.  **TypeScript 环境准备**
    *   初始化 `tsconfig.json`: 配置 TS 编译选项 (target: ES2020, module: commonjs/esnext)。
    *   安装 `@types/*`: 为 Express, Mongoose, Node 等安装类型定义。
    *   **关键文件**: `tsconfig.json`

### Phase 2: 测试体系构建 (Quality Assurance)
**目标**: 保证重构过程中的业务逻辑不丢失，建立信心。

1.  **测试框架搭建**
    *   引入 `Jest` (测试运行器) + `Supertest` (HTTP 断言)。
    *   配置测试环境数据库 (使用 `mongodb-memory-server` 或 Docker 独立容器)。
    *   **关键文件**: `jest.config.js`

2.  **编写基准测试 (Baseline Tests)**
    *   **优先**: 为核心 API (如 `GET /posts`, `POST /login`) 编写集成测试，确保接口契约不变。
    *   **其次**: 为复杂 Utils 工具函数编写单元测试。
    *   **关键文件**: `tests/integration/*.test.js`, `tests/unit/*.test.js`

3.  **CI 流水线**
    *   配置 GitHub Actions: 每次 Push/PR 自动运行 Lint 和 Test。
    *   **关键文件**: `.github/workflows/ci.yml`

### Phase 3: TypeScript 渐进式重构 (Migration)
**目标**: 将 JS 代码迁移至 TS，提升可维护性和安全性。

1.  **策略**: 采用 "Allow JS" 策略，逐步迁移。
2.  **步骤**:
    *   **Utils 层**: 优先迁移工具函数，定义清晰的输入输出类型。
    *   **Models 层**: 使用 Mongoose + TypeScript 定义数据接口 (Interface)，获得强大的模型类型提示。
    *   **Controllers/Services 层**: 迁移业务逻辑，显式声明 Req/Res 类型。
    *   **App/Routes 层**: 最后迁移入口文件和路由定义。

### Phase 4: 性能与安全加固 (Hardening)
**目标**: 提升系统吞吐量和抗攻击能力。

1.  **引入 Redis 缓存**
    *   缓存热点数据 (如首页文章列表、侧边栏推荐)。
    *   Session 存储迁移至 Redis (`connect-redis`)。
    *   **关键文件**: `utils/cache.js`, `config/redis.js`

2.  **安全中间件**
    *   `Helmet`: 设置 HTTP 安全头。
    *   `express-rate-limit`: 接口限流防爆破。
    *   `cors`: 严格跨域策略。
    *   **关键文件**: `middleware/security.js`

3.  **日志与监控**
    *   替换 `console.log` 为 `Winston` 或 `Pino` (JSON 格式日志)。
    *   添加全局错误处理中间件 (Global Error Handler)。
    *   (可选) 接入 Prometheus 监控指标。

### Phase 5: 高级特性 (Bonus)
**目标**: 增加简历亮点。

1.  **API 文档**: 集成 `Swagger` (OpenAPI)，自动生成接口文档。
2.  **消息队列**: 引入 RabbitMQ/Redis List 处理耗时任务 (如发送邮件、图片处理)。
